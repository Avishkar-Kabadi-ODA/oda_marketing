ODA MARKETING - CURRENT WORKFLOW AND BACKGROUND FLOWS
====================================================

ROLES
-----
Custom app role: Marketing Lead
Standard roles: Desk User, Employee, System Manager
Document roles: Writer = doc.assigned_to; Reviewer = doc.reviewer_technical
Format publisher: User configured on a Content Item Option

There are no database roles named Writer or Reviewer. The default publisher setting
is restricted by the Marketing Settings picker to Marketing Lead/System Manager/
Administrator. An assigned Lead is treated as the writer on that item for
self-review and self-publication checks.


CONTENT WORKFLOW
----------------

  Marketing Lead / System Manager
       |
       | Create item (Planned)
       | Planned items hidden from non-leads
       v
  [ PLANNED ]
       |
       | Issue Brief
       v
  [ BRIEFED ] -- assigned writer: Start Work; stamp brief_accepted_on
       |
       v
  [ IN PROGRESS ] -- writer updates draft and notes
       |              Due Date remains lead-controlled
       | Submit for Review (primary draft required)
       v
  [ IN REVIEW ] -- assigned reviewer: Approve or Request Changes
       |                                       |
       | Approve                               | Request Changes
       v                                       v
  [ APPROVED ]                            [ IN REVISION ]
       |                                       |
       | Lead / eligible format publisher      | assigned writer:
       | Publish (published_url required)      | Resubmit Draft
       v                                       |
  [ PUBLISHED ]                                +--> IN PROGRESS

`status` is synchronized with `workflow_state` during document validation.
Allowed workflow roles are real Frappe roles; Content Item server checks further
restrict each action to the assigned writer/reviewer, Lead, or eligible publisher.
Writers cannot review or publish their own item.


OPTIONAL AI COPILOT
-------------------

Writer action: Briefed / In Progress / In Revision
Reviewer action: In Review
       |
       | Server checks read permission, assignment/lead identity, state,
       | Markdown draft, enablement, and role-specific review limit
       v
  Enqueue after transaction commit (long queue, 600-second job timeout)
       |
       v
  [ Queued ] -> [ In Progress ]
       |              |
       |              +--> Stage 1: prompt-generation subagent
       |              |       deterministic fallback on prompt-generation failure
       |              +--> Stage 2: evaluator
       |                      |
       |                      +--> [ Completed ]: save score, feedback, history
       |                      +--> [ Failed ]: show retryable error
       |
       +--> Hourly recovery marks active jobs older than 30 minutes Failed,
            invalidates their token, and notifies the requester

Realtime stage updates are sent to the requester; the client reloads the Content
Item after completion. Role-scoped serialization keeps writer/reviewer feedback,
history, and reviewer instructions separated. AI results are informational only:
they never alter a workflow state.

LLM requests send both `Authorization: Bearer <key>` and `api-key: <key>`.
Supported live clients are OpenAI-compatible endpoints and Anthropic. Network and
provider failures are bounded and surfaced; evaluation failures do not create a
success-shaped review row.


HOURLY SLA JOB
--------------

  hooks.py: send_overdue_sla_notifications
       |
       +--> If automatic flagging is enabled:
       |      open items with due_date before today -> Late
       |      resolved/no-longer-overdue items -> clear stale Late flag
       |
       +--> During business hours [start, end):
              due-date reminders at configured/item offsets
              overdue notices for Late items
              one reminder/notice per item per date
              recipients: assigned writer and reviewer

The site timezone determines today/current hour. Default business hours are
09:00-19:00, with the end hour excluded. `last_sla_reminder_sent_on` and
`last_overdue_notified_on` prevent hourly duplicates.


SUPPORTING SURFACES
-------------------

  Content Item Option (Format / Industry Domain)
       +--> format dropdowns and optional format publisher
  Content Calendar
       +--> date-range validation and dashboard filters
  Marketing Settings
       +--> email templates, SLA settings, AI provider/limits/threshold
  Env Variable
       +--> encrypted provider values, permission-checked secret access
  Dashboard and Kanban
       +--> pipeline reporting; dashboard metrics are aggregated in SQL
  CSV/XLSX importer
       +--> Frappe File record -> confined site path -> Planned Content Items

Schema and data migrations are forward-only patches. `after_migrate` setup is
additive and does not replace existing workflows, templates, prompts, or dashboards.
